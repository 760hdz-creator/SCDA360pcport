## v0.1.18

### Faster in busy scenes (#26)
- **The game and the renderer now work at the same time.** Before, the game waited for the renderer to finish a
  frame before it started building the next one, so both costs added up. Now it builds the next frame while the
  current one is drawn, and it stays at most one frame ahead, so input lag doesn't grow.
- **Less work per frame:** shader constants are uploaded only where a shader actually reads them, and the
  command processor copies constant data in bulk.
- **Measured** in the Sea of Okhotsk snow scene from #26 (about 9,200 draws per frame) on a fast PC:
  - Before, about 1 frame in 5 took 50 ms instead of 33 ms (28 fps). Now that scene holds 30 fps.
  - With the 30 fps cap lifted for testing, throughput went from 28 to 37 fps (+31%).
- **Slower CPUs** should see a clear gain too, but busy scenes can still drop below 30 fps. Each draw still costs
  the renderer some CPU time, and that is the next thing to work on.

### Notes
